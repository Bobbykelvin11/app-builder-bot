# App Builder

Describe an app idea and get a starter Flutter `lib/main.dart`. The project has three parts:

| Part | Where | What it does |
| --- | --- | --- |
| Generator API + web UI | `vercel/` (deployed on Vercel) | `POST /api/generate` turns a prompt into Flutter source. `/` is a small web UI with copy and download. |
| Mobile app (Android + iOS) | `mobile/` (Flutter) | Generates code **on the phone** with an open-source model (default, offline), or optionally through the API. Templates, History and Settings tabs. |
| Legacy local server + Telegram bot | `server/` | Original FastAPI/Telegram starter for running on your own machine. Optional. |

> **Important:** App Builder writes source code. It is not compiled or tested, and it is not an installable app by itself. An unsigned IPA must be signed (for example with Sideloadly or AltStore) before it installs on an iPhone.

## Generator API (Vercel)

`vercel/api/generate.js` is a dependency-free Node.js serverless function.

```http
POST /api/generate
Content-Type: application/json
X-App-Key: <your APP_KEY>

{"prompt": "A habit tracker with streaks"}
```

Response: `{"file": "lib/main.dart", "code": "...", "model": "...", "provider": "..."}`.
Errors return `{"error": "<code>", "detail": "<human-readable message>"}` with 400, 401, 405, 429, 502, 503 or 504.

Features: shared-secret `X-App-Key` check (constant-time), prompt validation (8–4000 characters), best-effort per-IP rate limit (`RATE_LIMIT_PER_MIN`, default 6), upstream timeout (`OPENAI_TIMEOUT_MS`, default 50 s, function `maxDuration` 60 s), markdown-fence stripping, and redacted upstream errors.

### Environment variables (set in the Vercel project, never in git)

| Variable | Required | Purpose |
| --- | --- | --- |
| `APP_KEY` | yes | Shared secret clients send as `X-App-Key`. |
| `OPENAI_API_KEY` | no | If set, requests go straight to OpenAI (`OPENAI_MODEL`, default `gpt-4o-mini`). |
| `AI_GATEWAY_MODEL` | no | Model used when there is no OpenAI key (default `openai/gpt-4.1-mini`). |
| `AI_GATEWAY_API_KEY` | no | Only needed outside Vercel. On Vercel the function uses the deployment's OIDC token for **Vercel AI Gateway**, which includes free monthly credits. |

### Deploy

Create a Vercel project with **Root Directory = `vercel`** and framework preset **Other**, add the variables above, and deploy. Or from a terminal: `cd vercel && vercel deploy --prod`.

## Mobile app (v2.1)

`mobile/` is a Flutter project. Android and iOS platform folders are generated by `mobile/tool/prepare_platforms.sh`, which sets:

- Bundle / application ID: `com.bobbymedia.appbuilder`, display name **App Builder**
- Android `INTERNET` permission (model download and optional server mode)
- iOS deployment target **16.4** (required by llama.cpp via `llamadart`)

### On-device mode (default, open source, offline)

The app runs an open-source code model locally with [llama.cpp](https://github.com/ggml-org/llama.cpp) through [`llamadart`](https://pub.dev/packages/llamadart) (MIT) and `llamadart_llama_cpp_flutter` (iOS XCFrameworks, Metal). No server, no API key and no internet after the one-time model download.

| Model (Apache-2.0) | Download | Recommended phone |
| --- | --- | --- |
| **Qwen2.5-Coder-1.5B-Instruct Q4_K_M** (default) | 1.12 GB, [GGUF](https://huggingface.co/Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF/resolve/main/qwen2.5-coder-1.5b-instruct-q4_k_m.gguf) | 6 GB RAM or more (works on some 4 GB phones) |
| Qwen2.5-Coder-0.5B-Instruct Q4_K_M (smaller, weaker) | 0.49 GB, [GGUF](https://huggingface.co/Qwen/Qwen2.5-Coder-0.5B-Instruct-GGUF/resolve/main/qwen2.5-coder-0.5b-instruct-q4_k_m.gguf) | 3–4 GB RAM |

- **Model** tab: download with progress, pause/resume (HTTP Range), cancel, delete, and choose the model. Files live in the app's documents folder.
- **Build** tab streams the model's output as it is written, with a **Stop** button. It uses the same system prompt as the server and strips markdown fences.
- **Templates** tab: five ready-made, compile-checked starter apps (to-do, habits, tip splitter, Pomodoro, notes) that work with no model at all.

Caveats: generation speed depends on the phone (roughly 5–20 tokens/s for 1.5B on recent phones, so a full file can take one to several minutes). Keep the app open while downloading or generating. The unsigned IPA cannot use Apple's increased-memory entitlement, so on iPhones with less than 6 GB RAM pick the 0.5B model if the app is closed while loading. The model file is large; iOS may include it in device backups.

### Server mode (optional)

Settings → **Generation engine → Server** uses the Vercel API above (URL and App key in Settings).

### Screens

- **Build** – prompt with validation, examples, auto-saved draft, engine status.
- **Templates**, **History** (offline, swipe to delete), **Model**, **Settings** (engine, server URL/App key, theme, clear history).
- **Result** – selectable code with Copy and Share; shows whether it came from the phone, the server or a template.

```bash
cd mobile
bash tool/prepare_platforms.sh android
flutter build apk --release --split-per-abi --target-platform android-arm64
# optional server mode defaults:
#   --dart-define=API_BASE_URL=https://your-project.vercel.app --dart-define=APP_KEY=your-app-key
```

## Build APK / unsigned IPA with GitHub Actions

1. Optional: add a repository **secret** `APP_KEY` so the app ships with the key built in. Without it, users paste the key once in Settings. Never pass the key as a workflow input; inputs are shown in plain text.
2. Optional: add a repository **variable** `API_BASE_URL`, or type it in the run form.
3. Open **Actions → Build mobile artifacts → Run workflow**.
4. Download `android-apk` (universal + arm64 APK; arm64 is the one for almost every phone) and `unsigned-ios-ipa` from the run's **Artifacts**.

The workflow runs `flutter analyze` and `flutter test` first, then builds Android on Linux and iOS on macOS with Flutter 3.50.1.

## Legacy local server

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export OPENAI_API_KEY="your-key"
uvicorn server.main:app --reload
```

For Telegram, also set `TELEGRAM_BOT_TOKEN`, then run `python -m server.telegram_bot`.
